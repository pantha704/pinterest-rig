## Method, endpoints and reproducibility

`trends.pinterest.com` is a React app that renders an empty shell and fetches JSON client-side (`initialReduxState: null`), so the data source had to be read out of its own bundles. The URL builder is module `676143` in the served `.mjs` chunks — it assembles `https://<host>/<resource>/` plus query params — and the resource names live in the call sites. Recovered surface (all GET, all logged-out):

| Endpoint | Parameters that worked | What it returns |
|---|---|---|
| `/top_trends_filtered/` | `country`, `endDate`, `trendsPreset` (1-4), `lookbackWindow`, `rankingMethod`, `numTermsToReturn` | trending terms + `normalizedCount`, `searchCount`, `seasonality_score`, `mom_change`, `yoy_change`, `wow_change` |
| `/prefix_match/` | `query`, `country` | Pinterest autocomplete suggestions, each with a 52-week `counts[]` series normalised 0-100 |
| `/related_terms/` | `requestTerm`, `country`, `endDate`, `aggregation`, `lookback`, `predictedDays` | related searches for a term, with the same 52-week series |
| `/metrics/` | `terms`, `country`, `end_date`, `days`, `aggregation`, `normalize_against_group`, `predicted_days` | interest-over-time series for explicit terms |

`trendsPreset` values were established empirically, not guessed: **1** = top monthly (highest volume), **2** = top yearly, **3** = breakout/'trending now', **4** = growing/seasonal risers, **5** = rejected (400). No special headers or cookies are needed — plain `curl` with a browser User-Agent and a `Referer: https://trends.pinterest.com/` returns 200 with JSON.

## Blockers / caveats

- **Nothing blocked.** `trends.pinterest.com` served all trend data logged-out; no CAPTCHA, no login wall, no rate limiting was hit at 3-5 s spacing.
- **AU is not a supported trends region** — `country=AU` returns HTTP 400 `{}` for every preset (tried all four). US, GB, GB+IE, CA and DE all returned data. CA data is mixed English/French (`ongles d'automne`).
- **DE is included but noisy for a US/UK account**: the German view is full of greetings-card terms (`guten morgen gruss`, `geburtstagswünsche`, `gute nacht`) that are high volume on Pinterest but not commercially useful for affiliate pins. It is kept in `trends_DE.json` for completeness, not for targeting.
- **No `moments` / shopping-ads data**: `/resource/ApiResource/get/` (used for the trends shopping categories) returns 403 without a session cookie, so the shopping-ads product-category series were not harvested. Everything reported above is from the keyless trends endpoints.
- The VPS IP geolocates to **FR**, so the app's default region was France; every call here passes `country=` explicitly, which the endpoint honours.
- Request budget: **102 API requests** this run (~84 logged in `raw/reqlog.txt`), well inside the 200 cap, plus one headless-browser page load used to observe the app's own network calls.
